# Jury questions and grounded answers

| Question | Supported answer | Evidence |
|---|---|---|
| What differentiates another complaint app? | Explained priority, verified dispatch and proof-gated officer closure share canonical state; the drainage experiment adds inspectable context. | Three-role demo and audit |
| Are all flooded streets forecast already? | The storage experiment runs; surveyed inputs, live access and observed validation are needed for street forecasting. | Fixture, CSV and limits |
| Is IMD live? | Live ingestion is an integration task; demo rainfall is labelled synthetic and stale/missing radar is explicit. | Provenance/radar utility |
| Who validated P weights? | Team-configured weights need municipal calibration; contributions and sources are exposed. | Priority engine/chart |
| Does AI verify scene truth? | Pixel cues assist inspection; officers verify. No calibrated depth or fraud accuracy is claimed. | Review gate |
| Does SHA-256 prove cleaning? | It detects changed bytes; scene truth still needs evidence comparison and stronger capture validation. | Pair/digests/officer note |
| Can GPS be spoofed? | Client coordinates/accuracy are assertions. Server checks consistency; device attestation remains work. | Capture gates |
| Are routes flood-free? | OSRM alternatives are screened against known reports. Unknown hazards or insufficient alternatives can prevent recommendations. | Segment tests/unavailable states |
| What about no network? | Original bytes/time/key remain in the signed-in account's queue; retry waits for canonical server IDs. | Queue tests |
| Can one crew get two jobs? | The database enforces one active assignment. | Unique index/dispatch test |
| Can citizens see others' photos? | Raw intake remains owner-scoped, including after merging; relevant crew proof is shared. | Privacy regression |
| Where are impact percentages? | Field baseline/outcomes are required; this build reports test and numerical evidence without invented impact. | Validation/roadmap |
| Can other cities adopt it? | Workflow is reusable; local drainage/terrain, jurisdiction, policies and resources need configuration/testing. | Acceptance gates |
| Does FCM reach phones already? | Persisted updates work; optional sending needs credentials, enrolled devices and real delivery tests. | Outbox/sender |

Explain the demonstrated capability and the next validation step. Do not describe an adapter, fixture or design screenshot as an operational municipal deployment.
